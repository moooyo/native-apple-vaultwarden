# Apple UI implementation walkthrough

This is a source review, not a screenshot comparison. The [index](design/README.md) links all 39 original boards. The [handoff](HANDOFF.md) distinguishes the reference drawings from the three decisions that supersede them.

## Product corrections

- **Bottom search:** The [mobile shell](../../App/iOS/UI/MainTabView.swift) uses a real search-role tab on compact layouts. Selecting it opens the system field; dismissing it returns to the preceding tab. On a regular-width iPad, the [search control](../../App/iOS/UI/PadSearchField.swift) stays in the bottom safe area, rather than in the top tab bar. Opening search does not discard the underlying editor or navigation stack. Mac retains toolbar search and Command-K.
- **Settings, not an avatar:** The phone uses a labeled gear in the primary screens. The iPad uses a toolbar gear or a gear at the foot of the expanded sidebar. Neither platform assigns the search role to Settings. The Mac app has a separate Settings scene.
- **Supplied key artwork:** The [app icon](../../App/Shared/OpenVault.icon/icon.json), [fallback icon catalog](../../App/Shared/Assets.xcassets/AppIcon.appiconset/Contents.json) and [shared in-app mark](../../Sources/DesignSystem/Resources/Brand.xcassets/OpenVaultMark.imageset/Contents.json) use the supplied folded key. The menu bar uses a [monochrome template](../../App/Shared/Assets.xcassets/OpenVaultMenuBar.imageset/Contents.json) derived from its silhouette. Shield and lock symbols still identify vault and security actions; they are not the product logo.

## Boundaries and follow-up

- Vault edits can be queued offline. Folder and archive/trash mutations need a reachable server with the corresponding endpoints. An unsupported or failed server action must not be displayed as a successful local mutation.
- File Sends target direct uploads to self-hosted Vaultwarden, not Azure upload URLs. Send links include a secret fragment and should be shared only with intended recipients.
- Transfer supports personal Bitwarden JSON, password-protected PBKDF2 JSON, supported CSV layouts and a personal-vault subset of 1PUX. The form explains exclusions before export. CSV is not a full-fidelity backup. Unknown or unsupported input is not treated as a successful import.
- The Mac local edition still has no system AutoFill provider or biometric unlock. Sleep and session-lock controls use available public OS notifications; their behavior should be tested on a signed build.
- [Interface tests](../../Tests/Interface/UITests/NavigationTests.swift) specify bottom search and return, the settings gear, inline copy, undo/restore, sign-in, unlock, Send, picker privacy and iPad layout. They were **not run** for this handoff. Static Swift parsing does not perform SDK type checking.
- On Apple platforms, run the [simulator checks](../../App/README.md#simulator-ui-tests), then compare the layouts with the boards at their reference sizes. In particular, inspect keyboard focus and safe areas, dark mode, maximum Dynamic Type, Reduce Motion/Transparency, VoiceOver, and actual native glass rendering. Use a disposable vault to verify live sync, transfers and encrypted Send upload/download.
