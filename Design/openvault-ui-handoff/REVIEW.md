# Apple UI implementation walkthrough

The [index](design/README.md) links 38 product screens and the shared `Spec` board. The first pass mapped them to source; the November 22, 2026 pass compared native views with the original boards. The [handoff](HANDOFF.md) distinguishes the drawings from three intentional product changes. Fixture item names, counts and clock values are not visual acceptance criteria.

## Product corrections

- **Bottom search:** The [mobile shell](../../App/iOS/UI/MainTabView.swift) uses a real search-role tab on compact layouts. Selecting it opens the system field; dismissing it returns to the preceding tab. On a regular-width iPad, the [search control](../../App/iOS/UI/PadSearchField.swift) stays in the bottom safe area, rather than in the top tab bar. Opening search does not discard the underlying editor or navigation stack. Mac retains toolbar search and Command-K.
- **Settings, not an avatar:** The phone uses a labeled gear in the primary screens. The iPad uses a toolbar gear or a gear at the foot of the expanded sidebar. Neither platform assigns the search role to Settings. The Mac app has a separate Settings scene.
- **Supplied key artwork:** The [app icon](../../App/Shared/OpenVault.icon/icon.json), [fallback icon catalog](../../App/Shared/Assets.xcassets/AppIcon.appiconset/Contents.json) and [shared in-app mark](../../Sources/DesignSystem/Resources/Brand.xcassets/OpenVaultMark.imageset/Contents.json) use the supplied folded key. The menu bar uses a [monochrome template](../../App/Shared/Assets.xcassets/OpenVaultMenuBar.imageset/Contents.json) derived from its silhouette. Shield and lock symbols still identify vault and security actions; they are not the product logo.

## Iterative fidelity review

The review covered 16 iPhone, nine iPad and 13 Mac boards against the originals and the three approved product corrections. One round includes all reviewers; simultaneous platform reviews do not count as consecutive passes. A newly actionable finding resets the clean-round count. The exit criterion is two successive reviews without a new recommendation on the same candidate.

| Round | Findings and verification |
| --- | --- |
| 1 | Fixed selection and back navigation after creation, list copy/trash actions and inline feedback, and the distinction between unread and empty data. Checked the iPad editor size, insets and selection after creating outside a filter. On Mac, checked valid-code creation, hidden-item and Send search, keyboard defaults, editor and segmented-control sizing, account initials and export counts. Verified the last five seconds of a code also have a text cue. |
| 2 | Fixed retry instead of false empty states in the Mac lists, sidebar counts and menu panel; a recent-history failure no longer prevents a real vault search. Verified that cloning from Pinned selects an unpinned copy in All Items on iPad. Adjusted compact Settings: account, security and AutoFill groups measured 130/156/52 pt, with 47/46 pt gaps (references: 130/156/52 and 46/46). Captured the light and dark Mac Account panes with a known fixture KDF. |
| 3 | Fixed selection after saving a Mac Send under a search filter, including cancellation and delayed responses. Made irreversible deletion feedback distinguish confirmed local removal, an uncertain result and unattempted items; it stops at the first unconfirmed request. Shortened Send list durations to one updating unit without dropping access counts or the exact date in detail and accessibility. Matched the primary iPad tool captures to the boards' collapsed-sidebar state and kept separate expanded-state evidence. |
| 4 | The iPad Send board specifies accent-colored available glyphs but secondary titles and glyphs for expired or disabled entries. Native captures initially showed the same gray glyphs for every row and the detail header. Corrected the regular-width iPad treatment without changing the neutral glyphs on phone or Mac. Recaptured both sidebar states and checked that the badge and full access count remained legible in the narrow list. |
| 5 | On Mac, restored the initial Send sidebar count from existing, complete sync metadata (no extra request or decryption); put the single Send creation action in the list; and made all six verification cells equal within the 314 pt group. The countdown now changes color on the first five-second frame, independently of its width animation. Generator history uses directional dates, and unencrypted export warns with both an icon and a semibold lead-in. On iPad, restored pinned-first ordering, a readable selection that retains native navigation, and a readable-only item count in the expanded sidebar. Identified an earlier high-contrast Vault capture that no longer represented the candidate. |
| 6 | Compared the actual Mac Codes row activation with the original board handler. A click now selects the row and copies its current, ungrouped code even if already selected; selection without activation does not copy. The row acknowledges the action without exposing the code in the receipt. Unselected codes use the warning color in the last five seconds, and the filtered header describes results, including zero matches. In the iPhone Vault, the Increase Contrast sort caption went from 2.06:1 to 17.67:1 against the same background without changing its bounds. |
| 7 | Let an archived row show both its date and original folder beside Unarchive. Removed the extra dimming from the ordinary sort caption: its measured contrast changed from 1.71:1 to 3.29:1, matching the original reference without weakening Increase Contrast. Send now distinguishes a confirmed individual record from a complete account snapshot. The UI can show a newly saved item after a failed read without asserting a total or a false empty search; Retry recovers the full list. Offline reads require a verified complete snapshot, not an unrelated sync timestamp or a single cached record. |
| 8 | The product and state reviews identified no further changes, but ordinary iPhone screenshots captured after the simulator switched to dark appearance were paired with light references. The test fixture now sets light appearance for primary boards, explicitly opts into dark for the dark test and restores the device setting. Recaptured the phone boards. This evidence correction reset the clean-round count. |
| 9 | The primary boards now match the reference appearances. A refresh that removed the currently open iPhone Send could leave an empty detail sheet. The sheet now closes if the record is no longer present; a transient read failure retains the confirmed record and its detail. The real row accessibility label also repeated its metadata. Both visual layouts now share one accessible deletion-date and access-count summary. |
| 10 | An explicit 401/403 followed by an offline retry could redisplay a previously complete Send list. A denied list or full-sync request now invalidates only that account's snapshot. A single mutation, partial response or late read cannot restore it; fresh authorized complete data can. Eight repository and sync assertions reproduced the defect before the fix. The visible list, detail, draft and counts no longer depend on a second network request to clear them. A separate iPhone test backgrounds and reactivates the app, using the production lifecycle routine with a synthetic account: ordinary disconnection keeps the open detail; a 403 removes it even while the direct list is offline; only a new authorized complete response restores the list. |

All 16 ordinary phone screenshots use the same light appearance as the original boards; both intentional dark AX5 captures are separate. |

Two windows kept their selected Send details on ordinary disconnection, withdrew both details and their counts on a full-sync 403, and did not restore them from a late response. Retrying from each window recovered the new list. These two test runs are evidence, not two visual review rounds. |
| Builds and regression | Xcode 27.2 built all four targets: local Mac, full Mac, iOS simulator and iOS device. All 14 Swift package test programs passed, with 1,655 assertions and no failures. The local Mac app passed strict code-signature verification; the other three products contained the expected AutoFill provider. The device and full Mac builds do not certify signed system integration. |
| Copy at expiry | The iPhone test checked actual status pixels before copying, in the receipt frame and after it cleared. At AX1–AX4 the settled receipts showed 5, 5, 4 and 4 seconds, with at least 30 px between the status and the orange track. Mac samples show the six-to-five-second transition and the copied state in both the Codes list and Vault inspector. |
| Published gallery | The offline page passed checks for 39 navigable panels, 457 file and navigation links and 135 full-size image dimensions. WebKit decoded all 139 image instances; at 402 px wide the screen picker still navigated without horizontal overflow. |

The [offline gallery](../../build/ui-review/index.html) pairs the original boards with 32 phone/tablet captures, 30 Mac captures (15 in each appearance), and 24 additional simulator or system-settings captures. The 16 [comparison sheets](../../build/ui-review/contact-sheets/) and three [copy-at-expiry samples](../../build/ui-review/interaction-checks/) are included separately. Unaffected states use their last verified native capture; no additional product screen is counted for expanded iPad Send or the two Mac Account appearances. Apple's text-clipping audit passed at AX1–AX4 on Codes. In separate default-size display-setting checks it flagged compact account captions; the list deliberately permits shortened metadata, and its accessibility label includes the full account. These checks do not certify system VoiceOver, every string or overall contrast. The compact sort-caption ratios above are sampled native pixels, not a claim about the whole application.

## Boundaries and follow-up

The [functional review](../../Tests/Interface/FunctionalReview.md) records the subsequent
fixture interactions, isolated Vaultwarden run, affected-state visual rechecks, and work
that still requires signed devices. The original gallery is the earlier board-level record.

- Vault edits and confirmed permanent deletions can be queued offline. A deletion receipt reports what was removed from this device, not what the server has acknowledged. Folder changes, archive, move to trash and restore need the corresponding server endpoints. An unsupported or failed action must not be displayed as successful.
- File Sends target direct uploads to self-hosted Vaultwarden, not Azure upload URLs. Send links include a secret fragment and should be shared only with intended recipients.
- Transfer supports personal Bitwarden JSON, password-protected PBKDF2 JSON, supported CSV layouts and a personal-vault subset of 1PUX. The form explains exclusions before export. CSV is not a full-fidelity backup. Unknown or unsupported input is not treated as a successful import.
- The [current Mac build](../../App/README.md#mac-without-a-developer-account) supports local Touch ID unlock but does not ship a system AutoFill provider. Test sleep and session locking with the live Mac app rather than the offscreen host.
- The [simulator checks](../../App/README.md#simulator-ui-tests) drive the real views with an in-memory account; their AutoFill sheet is not a system credential-provider session. Verify App Group and Keychain sharing, biometric unlock, passkey registration/fill and extension memory on a signed iOS device. Use a disposable Vaultwarden account to verify live sync, imports, exports and encrypted Send uploads/downloads.
- The [Mac review host](../../Tests/Interface/MacReview.md) ran the native views on macOS 26.7.3. Inactive native window controls and minor system chrome differences are expected; these images do not establish keyboard or menu ownership across live windows.
